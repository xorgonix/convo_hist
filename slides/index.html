Convo Hist

A local-first archiver for your ChatGPT conversations

v0.5.0 — Library flow · Markdown vault · Digest engine

The problem

Your ChatGPT history is a black box

  • Thousands of conversations, locked behind one web UI
  • Search is shallow, no tags, no offline access
  • No way to back up, export, or keep what you built
  • If the account goes, the work goes

What it is

Every thread, as your own files

  • One JSON per thread — full, lossless, machine-readable
  • One Markdown per thread — with frontmatter, Obsidian-ready
  • Search, tags, summaries — computed locally
  • A Chrome side panel — no servers, no accounts, no telemetry

Design principles

Three rules, held since day one

  • Files are the source of truth. Browser storage holds only caches.
  • A line in the panel means a file on disk. The list is the library.
  • Be polite to the API. Paced, throttled, resumable — never hammer.

The flow

Two stages, two folders

STAGE 1 — DOWNLOAD                    STAGE 2 — EXPORT
ChatGPT ──► LIBRARY folder            LIBRARY ──► VAULT folder
one JSON per thread                   markdown + frontmatter
new & changed only                    markdown or JSON to a
paced · throttled · resumable         second folder (optional)

The library is the source of truth. The vault is the reading copy.

Stage 1

Download

  • Auto-runs when the panel opens; resumable forever
  • Diffs the live ChatGPT list against the library — fetches only new + changed
  • Pacing starts at 400ms; rate governor raises it to 8s when 429s appear
  • Server retry-after is honored exactly
  • Circuit breaker pauses after 3 consecutive failures — press Download to resume

Stage 1 output

The library folder

threads/
  Kubernetes Networking Deep Dive (6a113fa5).json
  Sourdough Starter Guide (6a11289e).json
  ...

Deterministic names — re-download overwrites in place. Title changes clean up the old file.

Stage 2

Export

  • Selected threads, or everything when nothing is selected
  • Diff-before-export: each library JSON is compared with ChatGPT's live list — stale threads are refreshed first
  • Writes markdown to the vault; optionally markdown/JSON to a second folder
  • Pure local disk writes — instant, no network

The panel

The list is the library

  • A line item means the JSON file exists on disk — nothing else is listed
  • Click = select for export · Select all at the top · double-click = export one
  • 📄J copies the thread's JSON · 📄M copies freshly-rendered markdown
  • Search box searches inside threads, not just titles

Settings

⚙ Everything configurable

  • Library folder — where downloaded JSONs live
  • Vault folder — markdown export destination
  • Second output folder — markdown or JSON
  • Summarizer — auto / Gemini Nano / Ollama / LM Studio / extractive
  • Ollama URL + model
  • Test button per folder — writes a marker file so you can verify the exact location in Explorer

Honest constraint

Why the "Test" button exists

The File System Access API cannot reveal a granted folder's full path — the browser hides it by design.

So Settings writes _convo_hist_here.txt into each configured folder. You look in Explorer and know.

Digest engine

Summaries + tags, four ways

1. Gemini Nano   — built into Chrome, on-device
2. Ollama        — localhost:11434, model auto-detected
3. LM Studio     — localhost:1234, OpenAI-compatible
4. Extractive    — built-in TextRank-lite, zero dependencies

LLM trouble degrades per-conversation to the fallback — the feature never fails.

Digest engine

What it writes

  • 2–3 sentence summary per thread
  • 3–7 lowercase tags, normalized
  • Written into the library JSON — then Export refreshes the vault
  • Search results show tag chips; summaries appear on result cards

Search

Inside the threads, not just the titles

hydration                    any message (fuzzy, prefix-matched)
code:                        only threads with code blocks
user: hydration              only your messages
assistant: networkpolicy     only assistant replies

Custom inverted index: IDF-weighted, grouped per conversation, snippet + highlight.

Resilience

Built for a hostile, unofficial API

  • Every fetch time-boxed (15s) — no silent hangs
  • 4xx answers are final — no wasteful duplicate retries
  • 429 → pacing doubles automatically, up to 8s; retry-after honored
  • Circuit breaker: 3 consecutive failures pause the batch, cleanly
  • Everything resumable — a paused run costs nothing to restart

Privacy

The data flow, in full

  • Reads chatgpt.com using your logged-in session — nothing else on the network
  • Writes only the folders you explicitly granted
  • No analytics, no accounts, no remote code
  • Browser storage: tiny caches (list, settings) — thread JSON lives in your folders

Verification

A browser-level test suite, not hope

  • Go + Rod: real Chromium, real extension, mocked ChatGPT API
  • 26 tests: smoke, journeys, edge cases, fault injection (401, 429, malformed)
  • Local TLS mock server covers panel and service-worker contexts
  • Screenshots, videos, per-test logs on every run

Verification in practice

A real defect it caught

  • Spec: re-capturing a renamed thread should remove the old files
  • Test proved it silently no-oped — code called a nonexistent handle.remove()
  • Duplicate files accumulated forever, invisibly
  • Fixed with dir.removeEntry(), re-verified — both results reported

Install

Five minutes

1. chrome://extensions → Developer mode → Load unpacked → extension/
2. Pin "Convo Hist" → click → side panel opens
3. ⚙ Settings → set Library + Vault folders → press Test on each
4. Download runs by itself
5. Export → your vault fills with markdown
